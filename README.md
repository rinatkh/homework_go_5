# Домашняя работа 5 — интерфейсы, аргументы main и файловый I/O

Домашка закрепляет занятие 5: интерфейсы, неявную реализацию, method set `T` и `*T`, маленькие интерфейсы, `io.Reader`, `io.Writer`, аргументы `os.Args`, работу с файлами и тестирование I/O.

## Разделы

| Раздел | Пакет | Количество задач |
|---|---|---:|
| Интерфейсы | `internal/interfaces` | 15 |
| Method set `T` и `*T` | `internal/methodsets` | 15 |
| `io.Reader` / `io.Writer` | `internal/ioflow` | 15 |
| Аргументы командной строки | `internal/cliargs` | 3 |
| Общие файловые задачи | `internal/common` | 3 |

Всего: 51 функция и метод.

Для каждой задачи предусмотрено 10 основных тестовых сценариев: обычный вход, граничные значения и ошибки. Дополнительный `TestExample` проверяет итоговый демонстрационный вывод раздела.

## Как не потеряться в объёме

51 функция и метод — это не 51 большой проект. Большинство заданий короткие и закрепляют одно конкретное правило. Не пытайся решить всё за один подход и не запускай полный `make ci` после каждой строки.

Работай небольшими блоками:

1. Выбери один раздел и 3–5 ближайших функций.
2. Прочитай условие функции в `docs/task.md`, затем TODO рядом с кодом.
3. Запусти тесты раздела и найди первый падающий тест.
4. Исправляй одну функцию, пока её сценарии не станут зелёными.
5. Сделай короткий перерыв и переходи к следующему блоку.

Рекомендуемый порядок прохождения:

| Этап | Что выполнить | Команда проверки |
|---|---|---|
| 1 | Интерфейсы: задачи 1–7 | `make test-interfaces` |
| 2 | Интерфейсы: задачи 8–15 | `make test-interfaces` |
| 3 | Method set: задачи 1–8 | `make test-methodsets` |
| 4 | Method set: задачи 9–15 | `make test-methodsets` |
| 5 | I/O: задачи 1–7 | `make test-io` |
| 6 | I/O: задачи 8–15 | `make test-io` |
| 7 | Аргументы командной строки | `make test-args` |
| 8 | Файловые задачи | `make test-common` |
| 9 | Общая проверка | `make ci` |

В стартовом проекте TODO ещё не реализованы, поэтому тесты сначала будут красными — это ожидаемо. Цель домашней работы заключается в том, чтобы постепенно сделать зелёным каждый раздел, а затем весь CI.

## Как выполнять

1. Сначала прочитай общий маршрут и описание первой функции в `docs/task.md`.
2. Затем открой TODO в нужном файле.
3. Реализуй задачи по порядку внутри одного раздела.
4. После каждого небольшого блока запускай тесты конкретного раздела.
5. В конце запусти полный CI.

## Команды

```bash
make compile
make test-interfaces
make test-methodsets
make test-io
make test-args
make test-common
make ci
```

## Важно

- Не меняй сигнатуры функций, структур и интерфейсов.
- Не удаляй тесты и не меняй ожидаемый вывод.
- В задачах на `io.Reader` и `io.Writer` не привязывайся к файлам, если функция принимает интерфейс.
- Помни, что `os.Args[0]` хранит путь запуска, а пользовательские аргументы начинаются с индекса 1.
- В файловых задачах используй `errors.Is`, когда нужно распознать `os.ErrNotExist`.
- После `os.Open` и `os.Create` файл нужно закрывать.
