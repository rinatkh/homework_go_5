# Задания к домашней работе 5

Перед выполнением задач прочитай этот файл и TODO рядом с каждой функцией. Тесты проверяют требования, но не являются единственным источником условия.

## Общие правила

- Не меняй сигнатуры функций и методов.
- Для функций, принимающих `io.Reader`/`io.Writer`, не привязывай решение к файлам.
- Для файловых операций закрывай файлы после успешного открытия.
- Там, где нужно распознать отсутствие файла, используй сравнение ошибки по смыслу, а не строку ошибки.
- `nil` и пустые коллекции обрабатывай так, как указано в таблице конкретной задачи.

## Как читать каждое задание

У каждой функции ниже есть четыре подсказки:

- **Что тренируем** — зачем функция находится в домашней работе.
- **Как рассуждать** — последовательность действий без готового кода.
- **Мини-пример** — конкретный вход и ожидаемый результат.
- **Частая ошибка** — место, на котором обычно ломается решение.

Не нужно сначала читать весь документ. Открой одну функцию, реализуй её и сразу запусти тесты текущего раздела. Если тест падает, читай имя сценария и сравнивай фактическое значение с ожидаемым. Полный `make ci` имеет смысл запускать только после прохождения отдельных разделов.

## 01 · Интерфейсы

### 1. User.String

**Сигнатура:** `func (u User) String() string`

| Вход | Вывод и правила |
|---|---|
| `User{ID, Name}` | Строка `user#<ID>:<Name>`. Имя не триммится, отрицательный ID сохраняется. |

**Что тренируем.** Метод value receiver и выполнение контракта `fmt.Stringer`.

**Как рассуждать.** Возьми `ID` и `Name` из получателя `u` и собери одну строку строго по шаблону. Ничего не проверяй и не исправляй: нулевой или отрицательный ID допустим, пробелы в имени нужно сохранить.

**Мини-пример.** `User{ID: 7, Name: "Maria"}` → `user#7:Maria`.

**Частая ошибка.** Обрезать пробелы в имени или использовать другой разделитель вместо `#` и `:`.

### 2. FormatOne

**Сигнатура:** `func FormatOne(value fmt.Stringer) string`

| Вход | Вывод и правила |
|---|---|
| Одно значение, реализующее `fmt.Stringer`, или `nil`. | Результат `String()`. Для `nil` — пустая строка. |

**Что тренируем.** Приём зависимости через стандартный маленький интерфейс.

**Как рассуждать.** Сначала проверь, равен ли сам интерфейс `nil`. Если нет, вызови его единственный нужный метод `String()` и верни результат без изменений.

**Мини-пример.** `FormatOne(User{ID: 1, Name: "A"})` → `user#1:A`; `FormatOne(nil)` → `""`.

**Частая ошибка.** Пытаться определить конкретный тип через type switch. Функции не важно, `User` это или другой `fmt.Stringer`.

### 3. FormatMany

**Сигнатура:** `func FormatMany(values []fmt.Stringer) []string`

| Вход | Вывод и правила |
|---|---|
| Слайс `fmt.Stringer`, внутри могут быть `nil`. | Строки ненулевых элементов в исходном порядке. Для `nil`/пустого входа — пустой слайс. |

**Что тренируем.** Работу со слайсом интерфейсных значений и сохранение порядка.

**Как рассуждать.** Создай пустой результирующий слайс, пройди по `values`, пропусти элементы, равные `nil`, а для остальных добавь результат `String()`. Пустая строка от `String()` остаётся полноценным результатом и не пропускается.

**Мини-пример.** `[User{1, "A"}, nil, User{2, "B"}]` → `["user#1:A", "user#2:B"]`.

**Частая ошибка.** Вернуть `nil` вместо пустого ненулевого слайса либо удалить элемент только потому, что его `String()` вернул пустую строку.

### 4. EmailNotifier.Notify

**Сигнатура:** `func (n EmailNotifier) Notify(message string) string`

| Вход | Вывод и правила |
|---|---|
| Адрес получателя и сообщение. | Строка `email:<Address>:<message>` без дополнительной валидации. |

**Что тренируем.** Создание конкретной реализации интерфейса `Notifier`.

**Как рассуждать.** Используй поле `Address` и параметр `message`, соединяя их с префиксом `email:`. Адрес и сообщение могут быть пустыми — функция всё равно только форматирует строку.

**Мини-пример.** `EmailNotifier{Address: "team@example.com"}.Notify("hello")` → `email:team@example.com:hello`.

**Частая ошибка.** Добавить не требуемую условием валидацию email или потерять двоеточие при пустом значении.

### 6. SendNotification

**Сигнатура:** `func SendNotification(n Notifier, message string) string`

| Вход | Вывод и правила |
|---|---|
| Notifier и сообщение. | Результат `Notify`. Для `nil` Notifier — пустая строка. |

**Что тренируем.** Функцию-потребителя, которая зависит от поведения, а не от конкретной структуры.

**Как рассуждать.** Проверь `n` на `nil`. Для ненулевого интерфейса просто передай сообщение в `Notify` и верни полученную строку. Не создавай внутри EmailNotifier или PushNotifier.

**Мини-пример.** `SendNotification(EmailNotifier{"a@b"}, "ping")` → `email:a@b:ping`.

**Частая ошибка.** Делать type switch по конкретным notifier-типам. Это разрушает смысл интерфейса и не позволит передать новую реализацию.

### 7. SendBatch

**Как рассуждать.** Для `nil` notifier верни пустой слайс. Иначе пройди по сообщениям по порядку, вызови `Notify` для каждого и добавь результат. Длина результата должна совпасть с длиной `messages`.

**Мини-пример.** Email notifier с адресом `e` и `[]string{"a", "b"}` → `[]string{"email:e:a", "email:e:b"}`.

**Частая ошибка.** Возвращать `nil` для пустого входа или переупорядочивать сообщения.

### 8. StaticLoader.Load

**Сигнатура:** `func (l StaticLoader) Load() (string, error)`

| Вход | Вывод и правила |
|---|---|
| Поля `Value` и `Err` внутри структуры. | Возвращаются ровно эти поля без преобразования. |

**Что тренируем.** Простую тестовую реализацию интерфейса, которая умеет возвращать и успех, и ошибку.

**Как рассуждать.** Метод ничего не вычисляет: первое возвращаемое значение берётся из `Value`, второе — из `Err`. Даже если ошибка не `nil`, значение не нужно самостоятельно очищать.

**Мини-пример.** `StaticLoader{Value: "data", Err: nil}.Load()` → `"data", nil`.

**Частая ошибка.** Создавать новую ошибку вместо возврата `Err` или менять `Value` при ненулевой ошибке.

### 9. LoadUpper

**Сигнатура:** `func LoadUpper(l Loader) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Loader, который возвращает строку или ошибку. | При успехе строка в верхнем регистре. При ошибке — пустая строка и исходная ошибка. `nil` loader — ошибка. |

**Что тренируем.** Обработку результата интерфейсного метода без потери исходной ошибки.

**Как рассуждать.** Сначала отдельно обработай `nil` loader и верни понятную ошибку. Затем вызови `Load()` один раз. Если loader вернул ошибку, верни пустую строку и ту же ошибку. Только успешное значение переводи в верхний регистр.

**Мини-пример.** Loader со значением `"Go Lang"` → `"GO LANG", nil`.

**Частая ошибка.** Игнорировать ошибку, преобразовывать строку при ошибке или заменять исходную ошибку новой без оборачивания.

### 10. Describe

**Сигнатура:** `func Describe(value any) string`

| Вход | Вывод и правила |
|---|---|
| Любое значение. | Описание динамического типа: `nil`, `string:<value>`, `user:<String>`, `notifier:<Notify ping>`, `loader:<value>`, `loader-error:<err>`, `error:<err>`, `unknown:<T>`. |

**Что тренируем.** Чтение динамического типа interface value через type switch.

**Как рассуждать.** Построй type switch по `value` в порядке из условия: `nil`, `string`, `User`, `Notifier`, `Loader`, `error`, неизвестный тип. Для каждой известной ветки сформируй именно указанный префикс. В ветке Loader вызови `Load`: успешное значение получает `loader:`, ошибка — `loader-error:`. Для неизвестного типа выведи его имя через формат `%T`.

**Мини-пример.** `Describe(User{1, "A"})` → `user:user#1:A`; `Describe(42)` → `unknown:int`.

**Частая ошибка.** Проверять только статический тип параметра `any`, забыть ветку `nil` или перепутать префиксы `loader-error:` и `error:`.

### 11. OnlyErrors

**Сигнатура:** `func OnlyErrors(values []error) []string`

| Вход | Вывод и правила |

**Что тренируем.** Фильтрацию интерфейсных значений и сохранение исходного порядка.

**Мини-пример.** `[nil, errors.New("one"), errors.New("two")]` → `["one", "two"]`.

**Частая ошибка.** Добавлять пустую строку для каждого `nil` или возвращать `nil`-слайс на пустом входе.

**Частая ошибка.** Жёстко приводить `a` к `*Counter`. Условие разрешает любую реализацию Adder, в том числе без Snapshot.

### 9. IsSnapshoter

**Сигнатура:** `func IsSnapshoter(value any) bool`

| Вход | Вывод и правила |
|---|---|
| Любое значение. | true, если динамический тип реализует `Snapshoter`. |

**Что тренируем.** Связь type assertion с method set динамического типа.

**Как рассуждать.** Выполни утверждение `value` к `Snapshoter` и верни флаг `ok`. Метод вызывать не нужно. Проверяется именно тип, поэтому typed nil указатель может реализовывать интерфейс и давать `true`.

**Мини-пример.** `Counter{}` → `true`; `Profile{}` → `false`; `(*Counter)(nil)` → `true`.

**Частая ошибка.** Считать любой nil значением, которое ничего не реализует: у typed nil остаётся динамический тип.

### 10. IsAdder

**Сигнатура:** `func IsAdder(value any) bool`

| Вход | Вывод и правила |
|---|---|
| Любое значение. | true, если динамический тип реализует `Adder`. |

**Что тренируем.** Разницу между method set `Counter` и `*Counter`.

**Как рассуждать.** Проверь type assertion к `Adder`. Так как `Add` объявлен с pointer receiver, обычный `Counter` не реализует Adder, а `*Counter` реализует.

**Мини-пример.** `IsAdder(Counter{})` → `false`; `IsAdder(&Counter{})` → `true`.

**Частая ошибка.** Решить, что раз `counter.Add()` компилируется у адресуемой переменной, то Counter можно присвоить интерфейсу Adder. Auto-addressing и method set — разные правила.

### 11. CloneAndAdd

**Сигнатура:** `func CloneAndAdd(c Counter, delta int) Counter`

| Вход | Вывод и правила |
|---|---|
| Counter и delta. | Новая копия с увеличенным значением; исходный Counter не меняется. |

**Что тренируем.** Явную работу с копией значения.

**Как рассуждать.** Параметр `c` уже передан по значению. Измени Value у этой локальной копии и верни её. Name должен сохраниться, а объект вызывающего кода — остаться прежним.

**Мини-пример.** Исходный `Counter{"c", 5}`, delta `2` → новый Counter со значением `7`, исходный остаётся `5`.

**Частая ошибка.** Создать новый Counter только с Value и потерять Name.

### 12. AddInPlace

**Сигнатура:** `func AddInPlace(c *Counter, delta int) int`

| Вход | Вывод и правила |
|---|---|
| Указатель на Counter и delta. | Меняет исходный объект и возвращает новое значение. `nil` -> `0`. |

**Что тренируем.** Отличие изменения копии от изменения объекта через указатель.

**Как рассуждать.** Для `nil` верни `0`. Иначе увеличь `c.Value` на delta и верни уже изменённое значение. Можно использовать метод Add, если это не усложняет решение.

**Мини-пример.** Counter со значением `4`, `AddInPlace(&counter, -1)` → возвращает `3`, внутри counter тоже `3`.

**Частая ошибка.** Вернуть правильное число, но не изменить исходную структуру.

### 13. Profile.Display

**Сигнатура:** `func (p Profile) Display() string`

| Вход | Вывод и правила |
|---|---|
| Profile. | Строка `<Name>(<Age>)`. |

**Что тренируем.** Метод чтения на ещё одном value-типе.

**Как рассуждать.** Отформатируй поля без валидации: имя, открывающая скобка, возраст, закрывающая скобка. Возраст может быть отрицательным, имя — пустым.

**Мини-пример.** `Profile{Name: "Maria", Age: 25}.Display()` → `Maria(25)`.

**Частая ошибка.** Добавить пробел перед скобкой или начать исправлять возраст, хотя условие этого не требует.

### 14. (*Profile).Rename

**Сигнатура:** `func (p *Profile) Rename(name string)`

| Вход | Вывод и правила |
|---|---|
| Указатель на Profile и новое имя. | Меняет `Name` у исходного объекта. `nil` receiver не паникует. |

**Что тренируем.** Pointer receiver и его влияние одновременно на мутацию и method set.

**Как рассуждать.** Проверь указатель. Если он ненулевой, присвой `name` полю `Name`; Age сохраняется. Новое имя может быть пустым или содержать пробелы.

**Мини-пример.** Profile `Maria(25)` после `Rename("Masha")` → `Masha(25)`.

**Частая ошибка.** Возвращать новую структуру вместо изменения исходной или менять Age.

### 15. IsRenamer

**Сигнатура:** `func IsRenamer(value any) bool`

| Вход | Вывод и правила |
|---|---|
| Любое значение. | true, если динамический тип реализует `Renamer`. |

**Что тренируем.** Закрепление правила pointer receiver через type assertion.

**Как рассуждать.** Проверь реализацию `Renamer` у динамического типа. Метод Rename есть только в method set `*Profile`, поэтому Profile и *Profile дадут разные результаты.

**Мини-пример.** `Profile{}` → `false`; `&Profile{}` → `true`; `(*Profile)(nil)` → `true`.

**Частая ошибка.** Проверять наличие поля Name вместо метода Rename.

## 03 · io.Reader / io.Writer

### 1. ReadAllText

**Сигнатура:** `func ReadAllText(r io.Reader) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Любой `io.Reader`. | Весь поток как строка или ошибка чтения. |

**Что тренируем.** Чтение данных из абстрактного источника, а не из конкретного файла.

**Как рассуждать.** Прочитай Reader до конца подходящей функцией пакета `io`. Если чтение завершилось ошибкой, верни пустую строку и ошибку; иначе преобразуй полученные байты в строку.

**Мини-пример.** Reader над строкой `"hello"` → `"hello", nil`.

**Частая ошибка.** Делать type assertion к `*os.File`: в тесте Reader может быть `strings.Reader` или специальный источник с ошибкой.

### 2. CountBytes

**Сигнатура:** `func CountBytes(r io.Reader) (int, error)`

| Вход | Вывод и правила |
|---|---|
| Любой `io.Reader`. | Количество байт в потоке. Для ошибки чтения вернуть ошибку. |

**Что тренируем.** Различие между байтами и символами при потоковом чтении.

**Как рассуждать.** Прочитай поток и посчитай именно байты. Можно направить данные в `io.Discard` или использовать результат полного чтения. Ошибку Reader обязательно верни вызывающему коду.

**Мини-пример.** `"hello"` → `5`; `"рус"` → `6`, потому что кириллические символы занимают несколько байт в UTF-8.

**Частая ошибка.** Считать руны или длину после преобразования в `[]rune`, хотя условие говорит о байтах.

### 3. WriteString

**Сигнатура:** `func WriteString(w io.Writer, text string) (int, error)`

| Вход | Вывод и правила |
|---|---|
| Writer и строка. | Записать строку и вернуть количество байт плюс ошибку записи. |

**Что тренируем.** Прямое использование контракта `io.Writer` и его двух результатов.

**Как рассуждать.** Преобразуй строку в подходящий для Writer вид или используй helper записи строки. Верни фактическое `n` и ту же ошибку, которые сообщил Writer.

**Мини-пример.** Запись `"рус"` в Buffer → `n=6`, содержимое Buffer равно `"рус"`.

**Частая ошибка.** Возвращать количество символов через `len([]rune(text))` или всегда считать запись успешной.

### 4. WriteLines

**Сигнатура:** `func WriteLines(w io.Writer, lines []string) error`

| Вход | Вывод и правила |
|---|---|
| Writer и строки. | Каждую строку записать с `\n`. При первой ошибке остановиться. |

**Что тренируем.** Несколько последовательных операций записи и ранний возврат ошибки.

**Как рассуждать.** Иди по `lines` по порядку. Для каждой строки запиши сам текст и один перевод строки. После каждой записи сразу проверяй ошибку; после первой ошибки больше ничего писать нельзя.

**Мини-пример.** `[]string{"one", "two"}` → `"one\ntwo\n"`.

**Частая ошибка.** Добавлять `\n` только между строками, хотя по условию он нужен и после последней строки.

### 5. CopyAll

**Сигнатура:** `func CopyAll(dst io.Writer, src io.Reader) (int64, error)`

| Вход | Вывод и правила |
|---|---|
| Источник и приёмник байт. | Скопировать весь поток и вернуть число байт. |

**Что тренируем.** Соединение Reader и Writer без знания их конкретных типов.

**Как рассуждать.** Используй стандартную потоковую операцию копирования из `src` в `dst`. Верни фактическое количество скопированных байт и ошибку чтения или записи без подмены.

**Мини-пример.** Источник `"abc"` и пустой Buffer → `n=3`, Buffer содержит `"abc"`.

**Частая ошибка.** Перепутать порядок аргументов: сначала у функции указан приёмник `dst`, затем источник `src`.

### 6. CopyUpper

**Сигнатура:** `func CopyUpper(dst io.Writer, src io.Reader) (int64, error)`

| Вход | Вывод и правила |
|---|---|
| Reader и Writer. | Прочитать текст, привести к верхнему регистру и записать в Writer. |

**Что тренируем.** Pipeline `Reader → преобразование → Writer`.

**Как рассуждать.** Сначала полностью прочитай источник и обработай ошибку чтения. Преобразуй строку в верхний регистр, затем запиши результат в `dst`. Возвращаемое число — количество записанных байт после преобразования.

**Мини-пример.** `"Go Lang"` → `"GO LANG"`, число байт соответствует итоговой строке.

**Частая ошибка.** Продолжать запись после ошибки чтения или возвращать длину исходной строки вместо результата Writer.

### 7. ScanLines

**Сигнатура:** `func ScanLines(r io.Reader) ([]string, error)`

| Вход | Вывод и правила |
|---|---|
| Reader с текстом. | Все строки без символов перевода строки. После цикла учитывать ошибку Scanner. |

**Что тренируем.** Правильный жизненный цикл `bufio.Scanner`.

**Как рассуждать.** Создай Scanner над Reader, вызывай `Scan()` в цикле и добавляй `Text()` после успешного Scan. После завершения обязательно проверь `Err()`. Для пустого входа верни пустой ненулевой слайс.

**Мини-пример.** `"a\nb\n"` → `[]string{"a", "b"}`.

**Частая ошибка.** Считать `Scan() == false` всегда обычным EOF и не проверить `scanner.Err()`.

### 8. CountNonEmptyLines

**Сигнатура:** `func CountNonEmptyLines(r io.Reader) (int, error)`

| Вход | Вывод и правила |
|---|---|
| Reader с текстом. | Количество строк, которые после `TrimSpace` не пустые. |

**Что тренируем.** Построчную обработку без сохранения всех данных в памяти.

**Как рассуждать.** Сканируй строки по одной, применяй TrimSpace только для проверки пустоты и увеличивай счётчик для непустых. После цикла верни ошибку Scanner, если она возникла.

**Мини-пример.** `"a\n\n  b  \n"` → `2`.

**Частая ошибка.** Посчитать строку из пробелов или забыть, что ошибка Scanner важнее накопленного счётчика.

### 9. FirstLine

**Сигнатура:** `func FirstLine(r io.Reader) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Reader с текстом. | Первая строка. Если строк нет — пустая строка без ошибки. |

**Что тренируем.** Получение первого токена и различение пустого ввода от ошибки.

**Как рассуждать.** Выполни первый `Scan()`. При успехе верни `Text()`. Если Scan вернул false, сначала проверь `Err()`: ошибка возвращается наружу, обычный EOF означает `"", nil`.

**Мини-пример.** `"first\nsecond"` → `"first"`; пустой Reader → `"", nil`.

**Частая ошибка.** Вернуть ошибку для пустого потока или пропустить пустую первую строку в тексте `"\nsecond"`.

### 10. ReadCSVLike

**Сигнатура:** `func ReadCSVLike(r io.Reader) ([][]string, error)`

| Вход | Вывод и правила |
|---|---|
| Текстовые строки с ячейками через запятую. | Таблица строк; у каждой ячейки убраны пробелы по краям. |

**Что тренируем.** Двухуровневую обработку: поток строк и разбор ячеек каждой строки.

**Как рассуждать.** Сканируй вход построчно. Каждую строку раздели по обычной запятой и примени TrimSpace к каждой полученной ячейке. Добавляй строку ячеек в таблицу, сохраняя порядок. В конце проверь Scanner.Err.

**Мини-пример.** `"a, b\nc,d"` → `[][]string{{"a", "b"}, {"c", "d"}}`.

**Частая ошибка.** Использовать полноценный CSV-парсер с поддержкой кавычек: по условию это упрощённый формат, где разделителем всегда служит каждая запятая.

### 11. LimitRead

**Сигнатура:** `func LimitRead(r io.Reader, limit int) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Reader и лимит байт. | Не больше `limit` байт. Отрицательный лимит считать нулём. |

**Что тренируем.** Ограничение объёма чтения независимо от размера источника.

**Как рассуждать.** Нормализуй отрицательный limit в ноль, затем создай ограниченный Reader и прочитай только его. Ограничение измеряется в байтах, а не в символах.

**Мини-пример.** `"abcdef"` с limit `3` → `"abc"`; с limit `0` → `""`.

**Частая ошибка.** Сначала прочитать весь исходный поток, а потом обрезать строку: тогда ограничение не защищает память и объём чтения.

### 12. RepeatToWriter

**Сигнатура:** `func RepeatToWriter(w io.Writer, text string, count int) error`

| Вход | Вывод и правила |
|---|---|
| Writer, строка и количество повторов. | Записать строку `count` раз подряд. `count <= 0` ничего не пишет. |

**Что тренируем.** Повторные записи в Writer и немедленную остановку при ошибке.

**Как рассуждать.** Для `count <= 0` сразу верни nil. Иначе выполни ровно count записей подряд без разделителей. После каждой записи проверяй ошибку.

**Мини-пример.** `text="ab"`, `count=3` → `"ababab"`.

**Частая ошибка.** Добавлять пробелы или переводы строк между повторениями либо продолжать цикл после ошибки Writer.

### 13. BufferReport

**Сигнатура:** `func BufferReport(lines []string) string`

| Вход | Вывод и правила |
|---|---|
| Слайс строк. | Строки формата `<index>:<line>\n`, собранные через Writer/Buffer. |

**Что тренируем.** Использование in-memory Writer для построения детерминированного отчёта.

**Как рассуждать.** Создай Buffer, пройди по строкам вместе с индексом и запиши для каждой индекс, двоеточие, исходную строку и `\n`. Верни содержимое Buffer.

**Мини-пример.** `[]string{"a", "b"}` → `"0:a\n1:b\n"`.

**Частая ошибка.** Начинать нумерацию с единицы или забыть перевод строки после последней записи.

### 14. ReadAndTrim

**Сигнатура:** `func ReadAndTrim(r io.Reader) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Reader. | Весь текст без пробелов по краям или ошибка чтения. |

**Что тренируем.** Композицию уже знакомых операций чтения и нормализации.

**Как рассуждать.** Полностью прочитай Reader, сначала обработай ошибку, затем примени TrimSpace к успешной строке. Пробелы внутри текста сохраняются.

**Мини-пример.** `"  hello world\n"` → `"hello world"`.

**Частая ошибка.** Выполнять TrimSpace над частичным результатом после ошибки или удалять внутренние пробелы.

### 15. WriteKeyValues

**Сигнатура:** `func WriteKeyValues(w io.Writer, values map[string]string) error`

| Вход | Вывод и правила |
|---|---|
| Writer и map строк. | Пары в отсортированном по ключу порядке, формат `key=value\n`. |

**Что тренируем.** Получение детерминированного вывода из map и обработку ошибок Writer.

**Как рассуждать.** Сначала собери все ключи map в слайс и отсортируй их как строки. Затем в этом порядке записывай `ключ=значение\n`, сразу возвращая первую ошибку записи.

**Мини-пример.** `map[string]string{"b":"2", "a":"1"}` → `"a=1\nb=2\n"`.

**Частая ошибка.** Итерироваться прямо по map и надеяться на стабильный порядок — Go его не гарантирует.

## 04 · Аргументы командной строки

### 1. UserArgs

**Сигнатура:** `func UserArgs(all []string) []string`

| Вход | Вывод и правила |
|---|---|
| Полный слайс в формате `os.Args`. | Вернуть новый слайс без элемента `all[0]`, потому что индекс 0 — путь запуска программы. Для `nil`, пустого слайса и только имени программы вернуть пустой ненулевой слайс. Результат не должен разделять backing array с входом. |

**Что тренируем.** Отделение системного элемента `os.Args[0]` от пользовательских аргументов и безопасное копирование слайса.

**Как рассуждать.** Если в `all` нет элементов после индекса ноль, верни созданный пустой слайс. Иначе создай новый слайс нужной длины и скопируй в него элементы начиная с `all[1]`. Простого `return all[1:]` недостаточно, потому что это будет view того же backing array.

**Мини-пример.** `[]string{"program", "Maria", "2"}` → новый `[]string{"Maria", "2"}`.

**Частая ошибка.** Вернуть `nil` для пустого ввода или вернуть `all[1:]`, после чего изменение результата неожиданно изменит исходный слайс.

### 2. Parse

**Сигнатура:** `func Parse(args []string) (Options, error)`

| Вход | Вывод и правила |
|---|---|
| Пользовательские аргументы без `os.Args[0]`: `<name> [repeat]`. | Имя обязательно и триммится. `repeat` необязателен, по умолчанию равен 1; если указан, должен быть положительным целым. Лишние аргументы запрещены. Для любого нарушения вернуть ошибку, распознаваемую через `errors.Is(err, ErrUsage)`. |

**Что тренируем.** Проверку внешнего ввода до обращения по индексам и построение понятной ошибки использования.

**Как рассуждать.** Сначала проверь количество аргументов: допустимы один или два. Затем обрежь пробелы у имени и отклони пустое значение. Установи Repeat в `1`; второй аргумент, если он есть, преобразуй в int и проверь `> 0`. Для всех нарушений возвращай `ErrUsage` напрямую или оборачивай её через `%w`, чтобы работал `errors.Is`.

**Мини-пример.** `[]string{"  Maria  ", "2"}` → `Options{Name: "Maria", Repeat: 2}`; `[]string{"Maria", "0"}` → ошибка ErrUsage.

**Частая ошибка.** Сначала прочитать `args[0]` или `args[1]`, а уже потом проверить len — при коротком слайсе программа получит panic.

### 3. Run

**Сигнатура:** `func Run(args []string, out io.Writer) error`

| Вход | Вывод и правила |
|---|---|
| Пользовательские аргументы и Writer. | Вызвать `Parse`, затем записать `hello, <Name>\n` ровно `Repeat` раз. Вернуть ошибку разбора или первую ошибку Writer. Не обращаться к `os.Args` и `os.Stdout` внутри функции. |

**Что тренируем.** Тестируемую CLI-логику с явными входом и выходом.

**Как рассуждать.** Передай `args` в Parse. При ошибке сразу верни её и ничего не пиши. При успехе выполни Repeat итераций и на каждой запиши одну строку приветствия в `out`. Если Writer вернул ошибку, немедленно остановись и верни её.

**Мини-пример.** `args=["Maria", "2"]` → Writer получает `"hello, Maria\nhello, Maria\n"`.

**Частая ошибка.** Читать глобальный `os.Args`, печатать через `fmt.Println` или игнорировать ошибку Writer. Всё взаимодействие с окружением уже остаётся в main.

Проверь реальный запуск после решения:

```bash
go run ./cmd/04_args "Maria Petrova" 2
make test-args
```

Кавычки обрабатывает shell: строка `Maria Petrova` попадает в программу как один элемент слайса. В `main` остаются только связи с окружением: `os.Args[1:]`, `os.Stdout`, `os.Stderr` и код выхода.

## 05 · Общие файловые задачи

### 1. ReadFileOrDefault

**Сигнатура:** `func ReadFileOrDefault(path string, defaultValue string) (string, error)`

| Вход | Вывод и правила |
|---|---|
| Путь к файлу и значение по умолчанию. | Если файл есть — содержимое. Если файла нет — default без ошибки. Другие ошибки вернуть. |

**Что тренируем.** Разделение ожидаемой ситуации «файла нет» и настоящих ошибок файловой системы.

**Как рассуждать.** Попробуй прочитать файл целиком. При успехе верни его содержимое. Если ошибка распознаётся через `errors.Is(err, os.ErrNotExist)`, верни defaultValue и nil. Любую другую ошибку нельзя скрывать — верни её наружу.

**Мини-пример.** Существующий файл с `"hello"` → `"hello", nil`; отсутствующий файл и default `"empty"` → `"empty", nil`.

**Частая ошибка.** Возвращать default для любой ошибки, включая отсутствие прав, либо сравнивать текст `err.Error()`.

### 2. WriteFileLines

**Сигнатура:** `func WriteFileLines(path string, lines []string) error`

| Вход | Вывод и правила |
|---|---|
| Путь и строки. | Создать/перезаписать файл, каждую строку записать с `\n`, закрыть файл. |

**Что тренируем.** Полный жизненный цикл Writer-файла: Create → Write → Close.

**Как рассуждать.** Создай файл и сразу обработай ошибку создания. После успешного Create обязательно запланируй Close. Записывай строки по порядку с одним `\n` после каждой, прекращая работу при первой ошибке. Если записи прошли успешно, не потеряй возможную ошибку Close.

**Мини-пример.** `[]string{"a", "b"}` создаёт файл с содержимым `"a\nb\n"`; nil-слайс создаёт пустой файл.

**Частая ошибка.** Поставить defer до проверки ошибки Create, забыть закрыть файл или потерять ошибку последней записи/закрытия.

### 3. CountFileLines

**Сигнатура:** `func CountFileLines(path string) (int, error)`

| Вход | Вывод и правила |
|---|---|
| Путь к файлу. | Открыть файл, посчитать строки через Scanner, закрыть файл, вернуть ошибки открытия/сканирования. |

**Что тренируем.** Потоковое чтение реального файла и обязательную проверку Scanner.Err.

**Как рассуждать.** Открой файл, проверь ошибку и только затем поставь Close. Создай Scanner, увеличивай счётчик на каждом успешном Scan. После завершения сначала проверь scanner.Err(); при нормальном EOF верни накопленный счётчик.

**Мини-пример.** Файл `"a\nb\n"` содержит две строки; пустой файл — ноль строк.

**Частая ошибка.** Не проверить Scanner.Err, считать завершающий `\n` отдельной строкой или вызвать Close для файла, который не удалось открыть.
